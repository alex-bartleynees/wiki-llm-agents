# Preview agent instruction drafts before saving

The draft endpoint accepts the provider and model choice, idea, optional name and description, and current instructions when explicitly included. It has no dependency on the agent catalog or config writer. Drafting uses the same one-shot completion path and timeout as Git commit suggestions.

The form and draft picker share each provider's discovery request and result for the life of the editor. Reselecting a provider in the form retries failed discovery and reuses a successful result. The provider-model HTTP endpoint shows the normal configured catalog. It is a suggestion source for the picker. Server validation of an explicit model runs in the draft's temporary directory. Claude Code uses its dedicated model lookup and bypasses the ordinary discovery cache. Codex and OpenCode use their existing provider model APIs and configured model catalogs. Omitting the model leaves the choice to the provider.

Claude Code and test Replay use their native one-shot completion methods. Claude Code uses the same SDK isolation options for lookup and generation, including empty filesystem setting sources, built-in tools and skills, strict empty MCP configuration, and disabled session persistence. Each query closes on completion or interruption, even if the SDK promise stalls. A model offered by the picker can be unavailable in isolation.

Alex approved the Git commit suggestion safeguards for Codex and OpenCode drafting. The shared completion path opens a fresh provider session in an empty scoped temporary directory with deny-all app autonomy, no vault tools, no project or attachment context, and only the drafting instructions and requested input. The app grants no approvals and supplies no user answers. It stops an unfinished turn on cancellation or failure and stops background work at the end of a finished turn. The shared completion keeps the turn stream alive during the five-second stop window. For Codex, this lets the adapter send `turn/interrupt` when it has the provider turn ID and cancel pending requests before stream teardown. If the turn handshake or stop stalls, cleanup proceeds to process termination. Codex sends SIGTERM and escalates to SIGKILL after two seconds if the child is still open. After the child exits, the launcher drains its output for up to 250 milliseconds before closing any pipes still held open by descendants. Complete replies received during the drain reach the RPC client before it rejects unanswered requests. The session waits for the child process to close before removing the temporary directory. The provider's native sandbox still controls filesystem access outside that directory. Codex and OpenCode can still load their native settings, plugins or tools and retain provider-native session history according to their normal behavior. The provider session is never registered as a wiki-agents thread. The fallback uses the existing sign-ins and provider configuration.

The editor cancels pending generation when the draft is discarded or the editor closes. It keeps returned text in a local preview. Applying it updates the form's Instructions field. The existing hash-checked save remains the only action that writes an agent file.

The Agents page and wiki pane share the catalog components. Each mounted catalog owns its selection. Wiki links carry a validated same-origin return destination through the editor and create-to-edit navigation. The editors use Agents as the default return destination. The app shell restores the phone's Agents tab when returning to its wiki entry.

On a cold Codex model lookup, each caller owns its app-server process. Cancellation during initialization or model discovery terminates that process and waits for close before the caller's temporary directory is removed. Concurrent callers share only a successfully completed model catalog through the cache. Cancellation or failure does not replace that catalog or stop another caller's process.

## Native isolation investigated before the fallback decision

Codex 0.169.0 reports a ChatGPT sign-in on the development host. Its generated experimental thread and turn schemas expose ephemeral sessions and environment controls, but the client protocol has no standalone text-generation operation or input for the internal tool allowlist. The recorded settings and ephemeral options therefore cannot establish the same isolation as the existing Claude drafting path. The public Responses API is a candidate for a separate text-only integration. API-key usage has separate billing. The Sign in with ChatGPT flow for local tools can use an eligible plan, with a separate app registration, OAuth credentials, consent and a plan-specific model catalog. Either integration needs product approval and verification of its retention behavior before enabling drafting. The experimental stateless text endpoint is declared in @opencode/protocol@2.2.1's dist/groups/generate.js. OpenCode 2.3.0's implementation builds a text-only request and creates no stored session. The HTTP handler waits for plugins from the base configuration before inference in both 2.2.1 and 2.3.0. The native CLI can disable project and Claude discovery, but its server bootstrap exposes no switch for global and system configuration. The underlying config service offers those switches to embedders. The published server's options omit them, and its fetch embedder can resume suspended agent sessions from its database at startup. That makes pointing an embedded runtime at the existing credential and session database an unsafe isolation shortcut. An isolated profile would need a supported way to reuse accounts without loading ambient plugins or resuming stored sessions, or separate credentials and an explicitly configured text-only integration.
