# Preview agent instruction drafts before saving

The draft endpoint accepts the provider and model choice, idea, optional name and description, and current instructions when explicitly included. It has no dependency on the agent catalog or config writer. Drafting requires a dedicated tool-free completion method and uses the standard one-shot timeout.

The form and draft picker share each provider's discovery request and result for the life of the editor. Reselecting a provider in the form retries failed discovery and reuses a successful result. The provider-model HTTP endpoint shows the normal configured catalog. It is a suggestion source for the picker. Server validation of an explicit model instead uses the provider's dedicated isolated model lookup. It runs in the draft's temporary directory and bypasses the ordinary discovery cache. Claude Code uses the same SDK isolation options for lookup and generation, including empty filesystem setting sources, built-in tools and skills, strict empty MCP configuration, and disabled session persistence. Each query closes on completion or interruption, even if the SDK promise has stalled. A model offered by the picker can be unavailable in isolation.

Claude Code and test Replay expose tool-free completion. The installed Codex 0.169.0 experimental ThreadStartParams schema supports ephemeral threads and optional dynamic tools and environments. Its TurnStartParams also supports disabling environments. Neither schema exposes an empty tool allowlist for built-in, hosted and plugin tools. The Codex exec ephemeral and ignore-user-config options address persistence and user configuration. Drafting also needs a documented guarantee that all tools are off. [Codex rust-v0.169.0 thread schema](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs) [Codex rust-v0.169.0 turn schema](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/app-server-protocol/src/protocol/v2/turn.rs)

The installed OpenCode protocol package @opencode/protocol@2.2.1 defines the experimental text endpoint in dist/groups/generate.js. The endpoint is stateless and uses the server's base configuration. Its payload offers prompt and model, with no settings or plugin isolation override. The app's installed OpenCode 2.3.0 supports separate servers, and OpenCode's configuration docs describe machine-wide settings and plugins with precedence over local settings. A private working directory alone cannot establish isolation from those inputs. The app leaves OpenCode and Codex out of the draft picker and rejects direct draft requests for them. A supported native isolation contract or a separately configured text-only API adapter would allow broader coverage. The existing general one-shot fallback remains available to existing callers. [OpenCode configuration](https://opencode.ai/docs/config) [OpenCode plugins](https://opencode.ai/docs/plugins/)

The editor keeps the returned text in a local preview. Applying it updates the form's Instructions field. The existing hash-checked save remains the only action that writes an agent file.

The Agents page and wiki pane share the catalog components. Each mounted catalog owns its selection. Wiki links carry a validated same-origin return destination through the editor and create-to-edit navigation. The editors use Agents as the default return destination. The app shell restores the phone's Agents tab when returning to its wiki entry.
