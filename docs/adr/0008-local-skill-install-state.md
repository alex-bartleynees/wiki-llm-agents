# Local skill installation state

The selected library is the source of truth. The server keeps the selected absolute paths in `skills-settings.json` in its data directory, which is host-local even when the library or config directory is synced.

The app records ownership, the installed digest and one rollback version per skill under `skill-installs/<SHA-256 of canonical destination>/<leaf skill>/` in host-local app data. A digest covers relative paths, bytes and modes. Preview returns a token bound to the reviewed versions and action. Apply rebuilds the review from disk before it accepts that token. A save to the library changes only `SKILL.md`.

The installer records the pending operation in app data and verifies a staged copy in a temporary hidden workspace on the destination filesystem. All live renames remain on that filesystem. The pending record lets the app finish a completed activation or restore the old directory after an interrupted replacement. Rollback bundles are copied and verified in app data. Modified installs, unowned paths and conflicting recovery files require manual resolution. Use one wiki-agents server per destination filesystem, and keep install destinations local to that host.

Discovery walks group folders until it reaches a bundle. The library-relative folder identifies the source, and provider destinations still use its leaf name. An installed bundle reserves that name for its recorded source path. Earlier records without a source path belong to the same-named library-root bundle and gain the path on their next managed change.

Configured destinations that resolve to the same directory share one ownership record and display all provider labels. Settings keep the entered alias and its resolved path so a link retarget requires review. Preview reports aliases and overlaps before any settings are written.

External installs are read-only. A directory symlink identifies its exact library folder. Copies must be valid skill bundles. An identical copy must match one library source, and a differing same-name copy requires a single candidate in the library. Ambiguous or unrelated entries remain unmanaged conflicts.

Detail requests only inspect state. An explicit Recover install action reconciles a pending operation or migrates a legacy destination record. An uncommitted operation without the moved directory’s recorded identity requires manual inspection if it left an old directory. A previous-format committed journal can retire after its state and rollback validate. Unverifiable workspace contents are left for manual inspection. The installer verifies and copies its rollback version into app data before publishing local ownership. It then removes the old record and verified legacy snapshots. Unknown files are left alone. Once local ownership exists, it takes precedence over any legacy remnants. An occupied directory without a verified management record remains external.

A local journal records the verified staging directory's device and inode. Recovery checks that identity and the digest at the live path before assigning ownership. The installer rechecks the old bundle after its move and restores a raced edit if the live path is still vacant. Committed cleanup checks the recorded transaction, workspace and remaining artifact identities, and rollback bytes. It can discard a partially cleaned workspace after an external change to the live bundle, which is then shown as locally modified. The Linux package and development shell ship a helper that uses renameat2 with RENAME_NOREPLACE for publication and restoration. An occupied target or unsupported filesystem aborts placement and preserves the pending transaction.

Cleanup makes only directories inside verified retired artifacts writable when needed for removal. A retry can continue from partially removed trees without changing the permissions of the live install or its retained rollback bundle.
